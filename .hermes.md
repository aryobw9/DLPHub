## Custom cursor + edge-band lessons (2026-09-17)
- Tauri `decorations:false` splits the window border between THREE owners. Measured on this box (96dpi, `SM_CXFRAME=CYFRAME=4`, `SM_CXPADDEDBORDER=4`):
  - **8px OS band** outside the client area (window rect 26,26 vs client origin 34,27) — webview never sees it. Only a `WM_SETCURSOR` subclass can restyle it.
  - **top 4px INSIDE the client area** — belongs to tauri-runtime-wry's `TAURI_DRAG_RESIZE_BORDERS` child HWND (its `SetWindowRgn` is literally `(0,0,1200,4)`), which always returns `HTTOP`. Clicks there never reach the DOM.
  - **everything else** — the webview owns it, so CSS/JS can style it.
  Probe it with `EnumChildWindows` + `GetWindowRgn`/`GetRegionData`; do not guess.
- `WM_SETCURSOR` for the border is delivered to the `TAURI_DRAG_RESIZE_BORDERS` **child**, not the parent. Subclassing only the parent window (the original `native_cursor.rs`) accomplishes nothing. Subclass both.
- `LoadImageW` on a filesystem path REQUIRES `LR_LOADFROMFILE` (0x0010). With `LR_DEFAULTSIZE` alone it parses the path as a resource name and returns NULL — silently, so the stock cursors stay. Verify: `LoadImageW(None, path, IMAGE_CURSOR, 64, 64, LR_LOADFROMFILE) != 0`.
- CSS `cursor: url(...)` on a `.png` larger than 32x32 can be ignored by the engine. 64x64 works in WebView2, but if a cursor silently refuses to apply, check size first.
- A `border-radius` of 40px on a 40x40 button clips the button's own hit area, while unclipped children (icon fonts, `<img>`) overhang the rounded corner — so the icon hit-tests to the parent row and the click dies on the icon. Fix: `.social-card::before { content:''; position:absolute; inset:0 }`. Generic rule: **rounded corners on small buttons + overhanging glyphs = dead click zones.**
- Cursor-cascade trap: `html[data-edge="e"] *` is (0,1,1) and out-ranks `html .win-ctl` (0,1,1 by source order? no — equal specificity, later wins), so the resize rule painted resize cursors over the titlebar buttons and social cards that sit in the 20px edge band. Beat it with (0,1,2): `html .window-controls button`.
- Click-through auditing without a browser: loop `document.elementFromPoint` over each control's bounding box and count how many samples resolve to the control or a descendant. Anything below 100% is a dead zone. This found the radius bug in one call.
- Build while the app is running fails with "Access is denied (os error 5)" on the exe. Kill it: `powershell -NoProfile -Command "Stop-Process -Name dlpbooster -Force"` (`taskkill //F` is mangled by MSYS path conversion).
